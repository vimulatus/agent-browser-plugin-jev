## Product

`soab` (system one agent browser), a command an agent runs with one goal or one policy file. It drives a browser, and Jev, the TypeSafe model, classifies what it shows and classifies what it shows, so the agent spends no tool calls on navigation and no thinking time between recorded actions.

**Stage:** walking, with evidence. The map is issue #1. The goal run, the policy engine, the bug-hunt policy, the walk and its repro evidence, and the login handoff are on main. It shipped first as an agent-browser plugin (0.1.0); from 0.2.0 it is a standalone command, because the plugin form was awkward to register and cut every call at 60 s. From 0.3.0 it is `soab`, a name not tied to one model; it was `jev` and `agent-browser-plugin-jev` before. The next map is #53: scopes, one store, sessions and a storage cap, all under the state directory `.soab` that `src/name.ts` derives from `NAME`. Every Jev reply in the tests is hand-written, but the goal run, a policy on one page, the walk and the walk's evidence have each run with a real key against agent-browser 0.38.1; a recording with Jev in the loop and the login poll on a real login page have not.

- **Users** — any agent that can run a shell command, and the people who run those agents. Today an agent drives a browser one command at a time and thinks between each one. First user: Vasu's coding agents.
- **Works when** — `npm install -g soab` puts `soab` on PATH, `soab run "<goal>"` lands on the goal page from one command, and `soab run --policy <file>` writes a `findings.json` an agent can turn into a report.
- **Non-goals** — no plugin protocol: the agent runs `soab`, and `soab` drives the browser. No change to agent-browser core. agent-browser is the only driver, behind the `Browser` interface in `src/browser.ts`; a Playwright or raw Chromium driver gets built only when a user needs what agent-browser cannot do. No text written by Jev: values come from the goal or a fixture file, because Jev only picks and judges. No destructive action unless the run allows it. Nothing that only one user's skills need.

## Ship

- **Run** — `pnpm install && pnpm build`, then `node dist/main.js run "<goal>" --session <name>`, or `node dist/main.js run --policy <file> --session <name>` to walk an app with no goal. `pnpm build && npm link` puts the local build on PATH as `soab`. Needs an installed `agent-browser` binary on PATH, and `TYPESAFE_API_KEY` for any run that reaches the model — without it a run writes `status: "failed"` to `<out>/status.json` and never opens the browser. A run blocks until it ends, prints one JSON line on stdout, and exits 0 when it reaches the goal and 2 when it is blocked; stderr names `<out>` first, and the login window when one opens. A walk that raises a finding replays it on a second session, `<session>-repro`, and records it, so it needs ffmpeg on PATH; `agent-browser doctor` says whether it is there.
- **Gate** — `pnpm test`. Tests replay recorded agent-browser output from `test/fixtures/` and Jev answers from `test/replay/`; they never open a browser or call the paid API. The Jev answers are written by hand to the documented response shape, so one manual check with a real key stays in the README.
- **Ship** — npm, as `soab`, from the trunk only. A PR bumps `version` in `package.json` (`npm version <x.y.z> --no-git-tag-version`; a fix is patch, a feature is minor). Once it merges: `git switch main && git pull`, `git tag -a v<x.y.z> -m v<x.y.z> && git push origin v<x.y.z>`, then `npm publish` (`prepare` builds `dist/`; the tarball is `dist/`, `policies/`, `SKILL.md` and the README). Verify with `npm view soab version`. Needs a valid npm login (`npm whoami`). The only bin is `soab`, and every usage line reads `NAME` from `src/name.ts`. Shipping 0.3.0, the first `soab`, takes two one-time steps: rename the GitHub repo to `vimulatus/soab` (the old URL redirects), and `npm deprecate agent-browser-plugin-jev "renamed to soab: npm install -g soab"`; the old package keeps its `jev` bins.
